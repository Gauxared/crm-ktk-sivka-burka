# Проверка локального воркера POC-002

Дата: 2026-09-13. Одна реальная генерация через центральный runner и TurboLLM.

**Итог: локальная модель быстро сформировала полезный черновик, но первая попытка
не прошла приёмку. После двух небольших исправлений ведущим результат проверен.**

## Что проверяли

Изолированная stdlib Python-функция summarize_cash: неизвестная цена, поступления,
возвраты, переплата, точные целые суммы, проверка входа и неизменность списков.
Это эксперимент в experiments/local-worker-002, не подключённый код CRM и не новый
платёжный модуль. Агрегатные суммы намеренно не ограничены API Money: тестируется
арифметика Python, а не готовый API денежных сводок.

## Качество исходной генерации

Независимый от реализации набор ведущего: 6 расчётных примеров, 13 некорректных входов
и неизменность списков — пройден исходной функцией. Этот набор был в контракте задачи
и виден модели; он не считается скрытым holdout-набором.

Тестовый файл модели не импортировался: перед class она вывела лишнюю букву,
строка `c class TestSummarizeCash(...)` дала SyntaxError. Следовательно, первый общий
validation — FAIL, результат не был автоматически принят.

Review нашёл вторую проблему: `_is_exact_int` использовала isinstance с исключением bool,
что всё ещё разрешало подклассы int. Контракт требует точный тип int. Дополнительные
проверки ведущего подтвердили принятие подкласса для total и поступления.

## Исправления ведущего

1. Удалена лишняя `c` перед class в тестах.
2. Проверка заменена на `type(value) is int`.
3. Добавлен один regression test с тремя подслучаями подкласса int: total, receipt, refund.

Повторной локальной генерации не было: retry_limit=0, выполнен явный cloud handoff.
Финальная проверка включает первоначальный контракт ведущего и 21 unittest
(20 исходных тестов модели после исправления синтаксиса и 1 regression test ведущего).

## Вывод для работы

Qwen/off пригодна как кандидат для небольших задач по точному контракту с обязательным
review. Эта попытка подтверждает около 35 токенов/с на коротком входе, но также показывает,
почему готовый ответ нельзя автоматически считать рабочим кодом. Для простой задачи
потребовались исправления ведущего. Архитектуру, авторизацию, транзакции и окончательную
приёмку оставляем облачной модели. Экономия облачных токенов и преимущество по общему
времени здесь не измерены. Результат одного задания не оценивает все способности модели.
