# Готовность к реализации — 2026-09-13

ARCH-008 согласует поля/ограничения доставки, циклы, аренды, аудит и операторские команды.
API 1.1, database 1.1 и notifications 1.1 — нормативные документы, не реализация.
Принятые услуги, ручное подтверждение/расчёты и допуск владельцем не изменены.

## Проверенное окружение

- Python 3.12.10 доступен, Node v24.19.0 доступен из bundled runtime Codex.
- Docker CLI 29.7.2 установлен, context desktop-linux; docker version не смог подключиться
  к dockerDesktopLinuxEngine. На момент проверки daemon не запущен/недоступен.
- psql и pg_ctl в PATH не обнаружены; это не полная инвентаризация всех установленных пакетов.
- До выгрузки локальной модели свободно 1 209 200 KiB RAM, после сообщения пользователя
  перепроверено 7 414 048 KiB (~7,1 GiB). Всего 16 642 456 KiB. Память меняется со временем.
- Свободное место на момент проверки: C около 70,7 GB, D 64,3 GB, E 191,8 GB (десятичные).
- Пакетные манифесты/Compose для приложения ещё не созданы. Стек backend/frontend,
  драйвер и средство миграций нужно зафиксировать перед установкой. POC на Python
  не считается автоматически выбранным стеком всего продукта.

## Следующий этап: окружение и первый работающий сценарий

1. Проверить возможность запуска Docker Desktop/Linux engine и выделение памяти.
   PostgreSQL размещать в отдельном volume вне синхронизируемой OneDrive-папки.
2. Зафиксировать минимальный стек и версии из официальной документации; поставить только
   необходимые зависимости. Локальная LLM не нужна и не запускается как часть приложения.
3. Подготовить воспроизводимые команды старта/остановки и тестовую PostgreSQL БД с
   синтетическими данными. Не использовать чужие существующие БД или production credentials.
4. Первый вертикальный сценарий: каталог → подача заявки → сохранение и receipt →
   просмотр владельцем. Очередь уведомлений сохраняется атомарно, доставщик на старте mock.
   Оба клиентских бота остаются в MVP, подключаются следующими задачами общего сценария.
5. Проверить SQL-ограничения, повтор после потери ответа и защиту приватного чтения.
   Затем календарь/группы/доставка по отдельным связанным задачам.

Никакая установка, запуск сервиса, отправка сообщения или создание миграций в ARCH-008
не выполнялись. Проверки этапа — согласованность документов, ссылки и scope.
До реального пилота остаются адресат Telegram, настройки обоих ботов, HTTPS/адрес клуба,
политика хранения реальных данных и тест восстановления резервной копии.
